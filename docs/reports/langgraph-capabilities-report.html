Executive Summary

LangGraph is a low-level orchestration framework and runtime for building stateful, long-running agents as directed graphs. Built by LangChain Inc., it uses a Bulk Synchronous Parallel (BSP) execution model inspired by Google Pregel. As of v1.2.6 (June 2026), it is the production-default choice for complex AI agent workflows requiring human-in-the-loop, durable execution, and multi-agent coordination.

Key stats: 35.8K GitHub stars, 549 releases, 280+ contributors, MIT license. Used by Uber, Klarna, LinkedIn, Replit in production. The framework provides a complete toolkit for agent orchestration: StateGraph for graph-based agent orchestration, built-in persistence via checkpointers, human-in-the-loop via interrupt()/resume(), multi-agent patterns (supervisor, swarm, sub-graphs, map-reduce), streaming (token-level to state-level), and deployment via LangGraph Platform.

LangGraph is not a high-level abstraction — it is a graph runtime where developers explicitly define nodes, edges, state schemas, and routing logic. This gives full control over execution flow, error handling, and state management, at the cost of a steeper learning curve (1–3 weeks for production readiness). The trade-off is worth it for teams building reliable, observable, production-grade agent systems.

Core Architecture

2.1 StateGraph

The primary entry point. Instantiate with a state schema, add nodes (Python callables), wire edges (static or conditional), and compile into a runnable graph.

from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    count: int

builder = StateGraph(State)
builder.add_node("agent", call_model)
builder.add_node("tools", ToolNode(tools))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", tools_condition)
builder.add_edge("tools", "agent")
graph = builder.compile(checkpointer=MemorySaver())
Key compile() Options

checkpointer, interrupt_before, interrupt_after, recursion_limit (default 25), debug, name

2.2 State Schema

Three schema types supported:

  • TypedDict — most common, lightweight
  • Pydantic BaseModel — validated, coerced
  • dataclass — mutable, but return new objects recommended

Annotated[T, reducer] attaches merge semantics to state keys:

  • add_messages — append + dedup by ID for chat history
  • operator.add — list concatenation, numeric sum
  • Custom reducers — any (current, update) -> new_value callable

2.3 Node Types

  • Function nodes: (state) -> dict or (state, config) -> dict or (state, runtime) -> dict
  • Async nodes: async def supported natively
  • LangChain Runnable nodes: ChatModel, chain, RunnableLambda
  • Subgraph nodes: compiled StateGraph as node
  • Command nodes: return Command(goto=..., update=...) for dynamic routing + state update

2.4 Edge Types

  • Regular: add_edge(START, "a"), add_edge("a", "b"), add_edge("b", END)
  • Conditional: add_conditional_edges("decider", router_fn, path_map)
  • Command: node returns Command(goto=...) for inline routing
  • Send: add_conditional_edges returning [Send("node", arg)] for fan-out

2.5 Execution Model — Pregel BSP Engine

State flows through supersteps:

  1. Read current state snapshot
  2. Execute all scheduled nodes (parallel if multiple)
  3. Apply outputs through reducers
  4. Resolve next nodes via edges

Within a superstep, all nodes see the same snapshot (read-only).

2.6 Compilation & Invocation

builder.compile() returns CompiledStateGraph wrapping a Pregel executor.

Multi-Agent Orchestration

3.1 Supervisor Pattern

Central coordinator routing to specialist sub-agents. Supervisor uses structured output (routing enum) to decide which worker to invoke. Workers are fully encapsulated — testable in isolation.

supervisor = create_supervisor(
    model=model,
    agents=[math_agent, research_agent],
    prompt="Route to the appropriate specialist.",
).compile()

3.2 Swarm Mode langgraph-swarm

Dynamic peer-to-peer handoffs. Agents call create_handoff_tool(agent_name) which returns a Command(goto=agent_name, graph=Command.PARENT). The swarm router reads active_agent after each step. Checkpointer is REQUIRED for swarm.

alice = create_react_agent(model, [add, create_handoff_tool("Bob")], name="Alice")
bob = create_react_agent(model, [create_handoff_tool("Alice")], name="Bob")
app = create_swarm([alice, bob], default_active_agent="Alice").compile(
    checkpointer=InMemorySaver()
)

3.3 Sub-Graph Composition

Compiled graphs as nodes with state isolation:

  • Shared by key (default): parent/child agree on overlapping keys
  • Input/output mapping: explicit schema projection
  • Sub-graphs inherit parent's checkpointer

3.4 Map-Reduce (Send API)

Dynamic fan-out for parallel execution:

def dispatch(state):
    return [Send("worker", {"item": item}) for item in state["items"]]

builder.add_conditional_edges("dispatch", dispatch, ["worker"])

Workers write to keys with reducers; runtime aggregates automatically.

3.5 Agent Handoffs (4 Mechanisms)

  1. Static add_conditional_edges — deterministic routing
  2. Tool returning Command(goto=...) — swarm handoffs
  3. Command(goto=...) from any node — stateful handoff
  4. Send(node, arg) — parallel fan-out

Persistence & Memory

4.1 Checkpointing Backends

BackendPackageUse Case
InMemorySaverlanggraph-checkpointDev/test
SqliteSaverlanggraph-checkpoint-sqliteLocal file
PostgresSaverlanggraph-checkpoint-postgresProduction
AsyncPostgresSaverlanggraph-checkpoint-postgresAsync production
RedisSaverlanggraph-redis (community)+ vector search

All implement BaseCheckpointSaver interface: get, put, put_writes, list, delete_thread.

4.2 Thread-Based State

  • thread_id in config["configurable"] identifies conversation lineage
  • checkpoint_ns for subgraph partitioning within a thread
  • checkpoint_id to pin to specific historical checkpoint

4.3 Time Travel

  • get_state_history(config) — iterator of StateSnapshot (newest to oldest)
  • Replay: invoke(None, config with checkpoint_id)
  • Fork: invoke(Command(resume=...), config with checkpoint_id) — branches history as tree
  • update_state(config, values, as_node=...) — surgical state mutation

4.4 Human-in-the-Loop

Three mechanisms:

  1. interrupt(payload) — suspends current node, returns resume value (PRIMARY)
  2. interrupt_before/interrupt_after — static breakpoints
  3. HumanInterrupt/Response protocol — structured HITL UI contract

Resume: Command(resume=value) or Command(resume={hash: value}) for multiple interrupts.

4.5 Memory Tiers

TierLifetimeAPI
Short-term (thread)Single threadState checkpoint
Long-term (store)Across threadsstore.put/get/search
Semantic (vector)Same as long-termstore.search(query=...)

BaseStore implementations: InMemoryStore, PostgresStore, RedisStore. Namespace hierarchy: ("users", user_id, "preferences")

4.6 Durable Execution

Automatic from checkpointer + interrupt(): every node's I/O is persisted.

  • Crash recovery: invoke(None, config) resumes from last checkpoint
  • durability parameter: "exit" (default), "async", "sync" (strongest)
  • Node side-effects must be idempotent for crash safety

Advanced Patterns

v1.2

8.1 Retry & Error Handling

builder.add_node("api", call_api, retry=RetryPolicy(
    max_attempts=3,
    initial_interval=1.0,
    backoff_factor=2.0
))

8.2 Timeouts v1.2

builder.add_node("slow", call_slow, timeout=TimeoutPolicy(
    run_timeout=60.0,
    idle_timeout=10.0
))

8.3 Error Handlers v1.2

def recover(error: NodeError) -> Command:
    return Command(update={"failed": True}, goto="fallback")

builder.add_node("primary", fn, error_handler=recover)

8.4 Graceful Shutdown v1.2

RunControl().request_drain() — saves checkpoint at next superstep boundary.

8.5 Node Caching v1.2

builder.add_node("retrieval", retrieve, cache_policy=NodeCachePolicy(ttl=300))

8.6 DeltaChannel v1.2

Incremental checkpointing — stores only deltas, critical for long threads. Reduces storage overhead significantly for conversations with large state updates.

oh-my-class Usage

OMC

This section details how the oh-my-class teaching pack generator leverages LangGraph for its multi-agent AI pipeline.

11.1 Graph Topology

8-stage teaching-pack graph:

setup_contract → preplanning_search → planning_blueprint → post_blueprint_research → artifact_workflow → render_quality → teacher_approval → export_finalize → END
Two Conditional Seams

render_quality → 4-way (planning_blueprint / post_blueprint_research / artifact_workflow / teacher_approval)

teacher_approval → 2-way (export_finalize / artifact_workflow)

11.2 State Schema

TeachingPackState TypedDict with:

  • run_id, contract, current_stage, completed_stages
  • lesson_plan, research_brief
  • artifacts, rendered_snapshots
  • quality_scores, quality_issues, quality_recovery_route
  • approval_gate, teacher_approved, teacher_decision
  • gate_payload, revision_feedback, approved_snapshot_ids
  • exported_files

11.3 HITL Pattern

interrupt(gate_payload) in teacher_approval node. Teacher POSTs Command(resume={action, feedback, rejection_type, artifact_rejections}). Scoped rejection loops back to artifact_workflow with narrowed artifact types.

11.4 Persistence

EnvironmentBackendNotes
ProductionPostgresSaverMulti-instance safe
DevelopmentMemorySaverLost on restart
StagingSqliteSaverFile: omc_checkpoints.db

Thread identity = run_id. checkpointing.py provides context manager.

11.5 Quality Gates

Two-layer check:

  • Deterministic: Pydantic validation, placeholder scan, answer-key leakage, pack coherence
  • Optional model-assisted: QualityGate protocol

Recovery routes map failing layer to earlier stage.

11.6 Scoped Regeneration

Teacher can reject individual artifacts. merge_regenerated_artifacts drops rejected items and appends fresh generation while preserving other artifacts.
