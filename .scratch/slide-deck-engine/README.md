# slide-deck-engine — issue set

Production-ready plan for a native `slide_deck` teaching-pack artifact and `SlideDeckEngine`. Local tracking only; no implementation has been done in this issue set.

Guiding principle: build a native, typed, standalone, quality-gated slide deck capability. Do not add `open-slide` or any React/Vite slide runtime dependency; use open-slide only as prior design research.

## ADRs

- `docs/adr/040-native-slide-deck-artifact-and-engine.md`
- `docs/adr/041-slide-deck-registries-and-interaction-modules.md`
- `docs/adr/042-slide-deck-surfaces-quality-and-release-gates.md`

## Locked decisions

- `slide_deck` is a core artifact type in `RunContract.artifact_types`.
- `SlideDeckData` is the canonical typed contract in `common/contracts`.
- `SlideDeckEngine` is a deterministic orchestration module behind the Content Creator seam.
- LLM steps are schema-bound; layout, interaction, density, accessibility, source refs, and teacher-only safety are validated deterministically.
- Full slide support comes from layout/block/interaction registries, not arbitrary HTML.
- Interactive modules are offline-first and non-persistent in v1.
- Media is two-tier: offline packaged/default, online optional with warning and fallback.
- Student presentation, teacher guide, and print HTML are separate surfaces from one canonical model.
- Student-facing output must contain no answer keys, correct answers, hidden answer JSON, teacher notes, or teacher-only fields.
- The existing artifact lifecycle, fanout, quality gates, teacher approval, scoped regeneration, and export finalize remain authoritative.
- Phase 1 exports standalone HTML surfaces only; PDF/PPTX are future exporters.

## Issue groups

**Foundation:** SD-01 contracts and domain model · SD-02 engine skeleton and registries.

**Tracer path:** SD-03 minimal native deck through content creator, fanout, renderer, quality, and export · SD-04 student/teacher/print surfaces and leak-safe projection.

**Production capability:** SD-05 interaction modules and media policy · SD-06 engine quality, healing, scorecard, and observability · SD-07 scoped regeneration and teacher feedback targeting.

**Teacher experience:** SD-08 slide-native preview UX in the existing teacher gate.

**Release proof:** SD-09 golden fixtures, visual smoke, and full output matrix coverage.

## Suggested execution order

1. SD-01 first; it creates the canonical contract and generated schema seam.
2. SD-02 after SD-01; it creates the engine interface, registries, and fixtures without graph integration.
3. SD-03 after SD-01 and SD-02; it proves a minimal end-to-end `slide_deck` artifact path.
4. SD-04 after SD-03; it hardens the three surfaces and answer-leak projection.
5. SD-05 after SD-04; it adds registered interactions and two-tier media policy.
6. SD-06 after SD-02 and SD-05; it adds typed healing, deterministic scorecard, and observability artifacts.
7. SD-07 after SD-06; it wires scoped regeneration semantics and feedback target maps.
8. SD-08 after SD-04 and SD-07; it adapts the teacher gate UX.
9. SD-09 depends on all prior issues and is the release gate.

## Out of scope for this issue set

- `open-slide` dependency or sidecar.
- Native PPTX export.
- Server-side PDF rendering service.
- Persistent student responses, analytics, or real-time classroom response collection.
- Arbitrary HTML/CSS/JS generated by LLMs.
