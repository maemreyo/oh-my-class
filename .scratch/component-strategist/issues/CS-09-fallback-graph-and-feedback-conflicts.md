## Parent

ADR-037.

## What to build

Implement the Component Strategist fallback topology and teacher-feedback conflict semantics. Production fallback must use reviewed fallback paths from strategy knowledge, preserve pedagogical intent before implementation simplicity, and return typed conflicts when teacher feedback would eliminate every valid path.

This issue owns fallback behavior as an end-to-end contract between knowledge entries, selector core, strategy revisions, Content Creator fill failures, gates, and teacher approval payloads.

## Acceptance criteria

- [x] Strategy knowledge supports explicit fallback graph entries between component bindings/learning moves, with preserved affordances, lost affordances, fallback quality, teacher message, and severity.
- [x] Every production-selectable binding declares `fallback_policy`: `required`, `terminal_safe`, or `no_fallback_allowed`.
- [x] Knowledge validation fails when a binding marked `required` has no valid fallback path, when fallback paths are circular, or when `no_fallback_allowed` lacks reason/severity/teacher options.
- [x] Runtime fallback ranking prioritizes core objective coverage, learning move intent, audience/export constraints, approved budget, strategy quality, then simplicity.
- [x] `evidence_balanced_basic` exists as an explicit fallback-only family/profile and is never offered as a normal selectable variant.
- [x] Content-fill repair ladder preserves approved slot/component before using fallback: retry fill, optional generation escalation, fallback component in same move, alternative move in same objective/phase, affected projection, whole-pack revision.
- [x] `prefer_component_family` is capped score influence and never a force command.
- [x] `reject_component_family` excludes a family only when a valid strategy remains; otherwise the engine returns typed `StrategyFeedbackConflict` with engine-authored options.
- [x] Explicit current-session teacher feedback conflicts are teacher-visible; implicit/default preference conflicts may auto-relax with audit warning.
- [x] Strategy revisions include materiality classification and `teacher_reapproval_required` when fallback changes teacher-visible pedagogy/scope.
- [x] Tests cover valid fallback, missing required fallback, circular fallback, no-fallback-allowed block, closest-intent ranking, explicit teacher conflict, implicit preference relaxation, and materiality classification.

## Implementation notes

- Do not infer production fallback paths from affordance similarity. Similarity may support validation/authoring diagnostics only.
- Do not silently switch scoring profile, drop core objectives, remove required exports, or change delivery context as fallback.
- Keep conflict options typed and generated by the strategy engine; the frontend only renders them.
