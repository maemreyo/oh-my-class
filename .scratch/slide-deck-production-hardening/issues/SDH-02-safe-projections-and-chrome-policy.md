## Parent

ADR-043: Slide Deck Display Preferences and Projection Boundaries

## What to build

Extend the slide-deck projection seam so every surface has an explicit data and chrome policy. Student and presentation surfaces must never contain teacher notes, answer keys, correct answers, acceptable answers, rationales, or hidden teacher-only payloads in the rendered HTML. Teacher surfaces may show teacher guidance outside the student canvas. Review surfaces should be deterministic and safe for quality/compliance scanning.

This slice should also remove robotic student-facing chrome by default. Student/presentation output must not show persistent “Generated by oh-my-class” text as classroom chrome. Teacher/review surfaces may show clear provenance, and print may show a small footer only when explicitly enabled by display preferences.

## Acceptance criteria

- [ ] Projection code recognizes the full surface set from ADR-043 or maps legacy values safely to it.
- [ ] Student and presentation projected data exclude teacher-only fields before template rendering, not by hiding them with CSS.
- [ ] Teacher-only answer data is absent from student/presentation HTML, including data attributes, inline JSON, hidden elements, scripts, and comments.
- [ ] Chrome visibility follows surface and preference policy: student/presentation default clean; teacher/review provenance visible; print footer optional.
- [ ] Quality/review projection remains deterministic and does not scan raw teacher-only data as if it were student-facing content.
- [ ] Technical guards assert no leakage for teacher notes, answer keys, correct option IDs, acceptable answers, and teacher rationales.
- [ ] A real generated deck from SDH-07 must later prove the same no-leakage behavior through actual export HTML.
